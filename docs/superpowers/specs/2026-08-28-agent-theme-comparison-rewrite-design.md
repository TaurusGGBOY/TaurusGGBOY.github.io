## 背景与问题

现有九篇文章以 Claude Code 源码解读的 00–48 节为骨架。前八篇共保留 50 个 `Section`，九篇合计有 87 个二级标题和 270 个三级标题。每个小节重复“Claude Code / Codex / Pi / 对比结论 / 验证动作”，读者需要先理解旧源码系列的目录，才能知道文章在回答什么。

这次重写不再修补旧结构。九个稳定 URL 保留，正文改为九个读者问题。公开文章、论文和官方文档是事实来源；本地源码、反编译结果和本站既有博文不进入证据链。DeepSeek Harness 从第一篇开始进入统一样本池，不再只出现在 A2A 附篇。

## 目标读者与成功标准

目标读者是正在使用或选型 coding agent 的工程师。他们知道模型、工具调用和上下文窗口，但不需要读过任何源码文章。

重写成功后，读者应能：

1. 区分模型、Harness、运行环境和任务四个变量；
2. 看懂 Claude Code、Codex、Pi 与 DeepSeek Harness 的核心设计取向；
3. 把功能差异还原成任务结果、风险、成本和监督负担；
4. 根据自己的工作流选择产品，或列出需要验证的条件；
5. 明白官方设计主张、独立实测和作者推断之间的证据差别。

每篇文章只回答一个问题，前 150 个汉字内给出答案。正文不再出现源码章节编号、源码路径清单、旧博文前置阅读要求或逐节重复的固定小结。

## 核心论点与比较单位

系列总论点是：

> 同一个模型，换一个 Harness，可能得到完全不同的 Agent。真正需要比较的是它如何看、如何做、如何验证，以及失败时由谁承担代价。

比较单位固定为：

```text
模型 × Harness × 运行环境 × 任务
```

没有控制这些变量时，文章只能描述当前公开设计或使用体验，不能推出“谁更强”。任何分数、速度或安全结论都必须同时说明任务、版本、资源、权限环境和证据来源。

## 九篇内容架构

九篇沿用现有文件、slug、series 和 order，改写标题、摘要、正文、topics、prerequisites 与核验日期。

### 01｜为什么不能只比模型

- 读者问题：模型能力和 Harness 能力怎样分开？
- 核心答案：Agent 的有效能力来自模型、Harness 与环境共同作用，产品榜单不能把差异都归给模型。
- 主要内容：Harness 的工作定义；为何工具、上下文、停止条件和运行环境会改变结果；四个项目的第一定位。
- DeepSeek Harness 角色：以“可重组运行时”进入样本池，同时标注 developer preview。

### 02｜一次 Agent 任务怎样跑完

- 读者问题：从一句需求到一次可交付变更，中间发生了什么？
- 核心答案：共同最小循环是获取上下文、调用模型、执行工具、回填反馈、验证并停止；差异在每一步由谁持有。
- 主要内容：上下文进入、工具反馈、失败重试、完成信号；用同一个修复任务贯穿四个项目。
- 禁止写法：不按工具数量列功能，不展开实现函数。

### 03｜Agent 什么时候必须停下来问人

- 读者问题：权限弹窗、审批和沙箱分别防什么事故？
- 核心答案：沙箱限制技术上能做什么，审批决定何时交还决策，外部隔离控制最坏损失；三者不能互相替代。
- 主要内容：文件、网络、凭据和进程边界；一次性提权；审计与恢复。
- DeepSeek Harness 边界：写清官方未安全审计、不能作为不可信任务唯一安全控制。

### 04｜长任务怎样保持上下文并恢复

- 读者问题：任务运行数小时或跨会话后，约束、进度和失败如何不丢？
- 核心答案：长任务依赖高信号上下文、显式交接物、可恢复会话和可纠正记忆，不是只靠更大的上下文窗口。
- 主要内容：压缩、会话树或事件日志、恢复与分叉、跨会话说明、记忆的可信度。
- DeepSeek Harness 角色：比较 append-only session event log 与其他项目的 session/transcript 设计。

### 05｜CLI、IDE 与云端由谁持有运行状态

- 读者问题：同一个 Agent 出现在终端、IDE、桌面端或云端时，控制权在哪里？
- 核心答案：宿主不是皮肤；它决定会话生命周期、事件协议、审批入口、并发与远程恢复。
- 主要内容：Claude Code 的产品工作台、Codex 的跨客户端 Harness/App Server、Pi 的 TUI/RPC/SDK、DeepSeek Harness 的 profile 与可替换 UI/runtime。
- 比较结果：区分“产品表面很多”和“同一运行状态可被多个客户端可靠驱动”。

### 06｜扩展能力应该装插件还是改运行时

- 读者问题：Skills、Hooks、MCP、Provider 与插件究竟改了哪一层？
- 核心答案：扩展价值取决于插入位置、作用域、生命周期和信任边界，而不是扩展项数量。
- 主要内容：四个项目如何放置持久说明、按需知识、外部工具、事件拦截与模型适配。
- DeepSeek Harness 角色：重点解释“一切皆插件”与可替换 loop/session/sandbox 的设计假设，并明确尚无独立性能证明。

### 07｜多 Agent 是委派工具还是组织系统

- 读者问题：什么时候需要 subagent，什么时候需要团队、工作流或跨产品协议？
- 核心答案：上下文隔离、并行委派、持续协作和跨组织互操作是四个不同层次。
- 主要内容：subagent、agent team、workflow、异构 provider；A2A 只作为跨边界层出现，不再写协议史。
- DeepSeek Harness 角色：比较其可并存 Codex、Claude Code、ACP 等 provider 的异构编排能力。

### 08｜Agent 如何证明任务真的完成

- 读者问题：最终回复说“完成”时，应该相信什么证据？
- 核心答案：完成必须落到测试、静态检查、运行态验证、Trace 和可审计的停止条件。
- 主要内容：环境反馈、失败归因、外部 reviewer、回归样本；成功率之外还要看 token、延迟、重试、无行动回合和人工监督时间。
- 证据边界：不从官方功能文档推导独立质量排名。

### 09｜Claude Code、Codex、Pi、DeepSeek Harness 怎么选

- 读者问题：四个项目分别适合什么人和什么工作流？
- 核心答案：Claude Code 偏集成式工作台，Codex 偏跨表面的可靠执行层，Pi 偏可塑的最小 Harness，DeepSeek Harness 偏可重组的 Agent 运行时。
- 主要内容：按任务复杂度、隔离责任、定制深度、并行需求、成熟度和监督成本给条件式建议。
- 禁止写法：不设总冠军，不把 developer preview 写成生产就绪。

## 单篇叙事模板

每篇使用同一阅读节奏，但不机械重复同一组小标题：

1. 用一个具体事故或选型场景开篇；
2. 在前 150 个汉字给出本篇答案；
3. 定义本篇唯一比较问题和证据边界；
4. 让四个项目面对同一任务或事故模型；
5. 按“观察到的设计 → 对任务结果的影响 → 谁需要在意”解释差异；
6. 用一张小表汇总必要映射，不用勾选表承担论证；
7. 以条件式结论结束，并自然引向下一篇；
8. 在文末列出本篇实际引用的公开来源。

目标长度为每篇 2,500–4,000 个汉字。二级标题原则上不超过 7 个；三级标题只在同一节确有并列概念时使用。

这些定位是系列的导航，不是不可修改的判词。文章中的具体能力仍以 2026-08-28 可访问的公开资料为准。

| 项目 | 稳定定位 | 不应越过的证据边界 |

| Claude Code | 集成式 Agent 开发工作台 | 官方文档说明产品行为，不证明所有任务上质量最高 |

## 证据与引用规则

研究证据包位于 `~/Documents/Agent_Harness_Comparison_Research_20260828/`，当前包含 31 个来源和 26 条原文证据。

证据优先级为：

1. 官方文档、官方工程文章和项目 README；
2. 同行评审论文或公开方法、数据和限制的预印本；
3. 项目作者文章和带方法说明的独立实测；
4. 一般评论只用于发现问题，不承担核心结论。

所有事实紧邻来源链接。设计归纳使用“官方文档显示”“该设计意味着”；跨项目推断使用“在本文比较条件下”；没有控制变量的结果不得写成性能排名。发布日期缺失时标注访问日期。

本地源码、反编译结果、本站旧文和旧稿中的数字不得回流成新稿证据。旧稿只用于保留 URL、系列顺序和站点元数据约束。
